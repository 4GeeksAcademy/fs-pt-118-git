Reglas para no perder la cabeza con git

  1. LO QUE NO TE TOCA, NO SE TOCA
  2. en main/master NO se trabaja
  3. Siempre debe de crearse una rama develop y NO se trabaja en ella
  4. antes de comenzar a trabajar, hacer un pull de develop
  5. mi rama siempre tiene que estar sincronizada con develop. cada vez que se haga un PR, yo tengo que hacer pull
  6. git add . / git add archivo-a-añadir.extension
  7. git commit -m 'conventional commit'
  8. antes de cada push, viene un pull
  9. git pull origin develop
  10. el push SIEMPRE a la rama donde estoy trabajando
  11. git push origin mi-rama-de-trabajo
  12. voy a github y hago PR
  13. si hay conflictos al hacer el PR, se solucionan en el codespace/VSCode
  14. aviso al resto de compis que se realizo un PR
